    under a name, <strong>Load</strong> restores them,
    <strong>Defaults</strong> restores the factory starting values (Min Size 3,
    Min Features 5, quality 80/70/60, Min Occur 3). Presets live in
    <code>localStorage</code> and persist across sessions.
  </p>
  <h4>Clusterability</h4>
  <p>
    A single SNP run cannot tell you whether the thresholds were too strict or
    whether the data simply has no structure this method can find — both come
    back as zero groups. <strong>Clusterability</strong> answers that by running
    the SNP grouper across a spread of settings: each parameter varied on its
    own from your current values, plus the loosest combination the panel allows.
    It reports, for every run, how many groups formed, how many sequences were
    assigned, and the largest group.
  </p>
  <p>The summary above the table names three things:</p>
  <ul>
    <li>whether the alignment groups <em>at all</em>, and under which settings it did best</li>
    <li>which parameters <strong>changed</strong> the outcome</li>
    <li>which parameters had <strong>no effect anywhere in their range</strong> — where further tuning is wasted effort</li>
  </ul>
  <div class="note">
    <strong>Note:</strong> Clusterability only surveys — it reads your parameters
    and leaves them exactly as they were. Nothing is applied. Choose the settings
    you want and press <strong>Find SNP groups</strong>. A full survey takes tens
    of seconds on a large alignment, and the table fills in row by row as each
    run finishes.
  </div>
  <p>Typical workflow:</p>
  <ol>
    <li>Trim ends with Preview → Trim</li>
    <li>Optional: <strong>Group by k-mer</strong> for an overall split</li>
    <li>If unsure whether exclusive SNPs exist, press <strong>Clusterability</strong></li>
    <li>Click <strong>Find SNP groups</strong> (optionally with Split existing groups)</li>
    <li>Review the Group explorer; copy FASTA or insert a consensus below selected rows</li>
    <li>Optional: <strong>Show 2D</strong> to see where those patterns sit as rectangles</li>
  </ol>
  <div class="note">
    <strong>A zero result is a threshold result.</strong> When no SNP group forms,
    the results panel names the settings that discarded everything and quotes
    their current values. Lowering <strong>Min Size</strong> is usually what
    admits small groups: at Min Size 3, sequences that pair up two at a time
    are all rejected, so an alignment whose structure is pairwise reports zero
    groups until Min Size is 2.
  </div>
  <p>How Find SNP groups works:</p>
  <ul>
    <li>At each alignment column, sequences are grouped by shared nucleotide</li>
    <li>Groups meeting the size and quality thresholds are collected as candidates</li>
    <li>Near-identical groups are fuzzy-merged (Jaccard similarity &gt;= 90%, and the two groups differ in size by at most 5 sequences)</li>
    <li>Perfect-unique positions (all members share a base unique to that group) get highest weight</li>
    <li>Outliers are pruned: in a group with more than 2 diagnostic features, a member must match at
    least 2 of them (groups with up to 5 features) or at least 30% of them, rounded up (larger groups)</li>
    <li>The algorithm iterates with progressively relaxed thresholds to recover smaller families</li>
  </ul>

  <h3 id="cl-2d">4.4 2D analysis</h3>
  <p>
    <strong>Show 2D</strong> draws translucent rectangles over stretches where a
    subset of rows share a local pattern. This is a separate overlay from name
    and letter colours. It does not change row order. It works in Full, Block and Canvas
    views, including the windowed Full display used above about 100,000 residues.
  </p>
  <p>
    If SNP or k-mer groups already exist, each rectangle is tagged against them:
  </p>
  <ul>
    <li><strong>supporting</strong> — the boxed rows match a current group</li>
    <li><strong>inside</strong> — the boxed rows sit inside a larger group</li>
    <li><strong>discordant</strong> — the boxed rows cut across current groups</li>
  </ul>
  <p>
    A status line reports rectangle count and, when groups exist, those three
    tallies. Running a new grouping retags a live overlay. A count of
    “0 support, 0 inside, 0 discordant” with “no groups to compare” means no
    grouping has been run yet, not that the rectangles failed.
  </p>
  <table>
    <tr><th>Control</th><th>Meaning</th></tr>
    <tr><td>Show 2D</td><td>Compute and draw rectangles</td></tr>
    <tr><td>Clear</td><td>Remove only the rectangle overlay. Name and letter colours stay until you Clear them in k-mer groups or Diagnostic SNPs</td></tr>
    <tr><td>Group rows</td><td>Does not stack by itself. Prompt: Alt+click a coloured rectangle to stack that type, including scattered copies. Undoable</td></tr>
    <tr><td>All copies, one box</td><td>One rectangle covers every sequence with that pattern, even if those rows are not next to each other</td></tr>
    <tr><td>Stack + copies</td><td>The contiguous stack is one rectangle; scattered copies get a second, paler layer</td></tr>
    <tr><td>Stack only</td><td>Paint only the contiguous stack. Scattered copies of the same pattern are left unpainted</td></tr>
    <tr><td>Opacity</td><td>How solid the rectangles are drawn</td></tr>
  </table>
  <p>
    Paint modes never change alignment order. Plain click on the alignment still
    selects nucleotides (two clicks extend the range). <strong>Alt+click</strong>
    a rectangle to stack that type. Terms used in tooltips:
  </p>
  <ul>
    <li><strong>Type</strong> — sequences that share the same pattern in the same column range</li>
    <li><strong>Rectangle</strong> — that type drawn on the alignment. One type may paint as several boxes if members are not sitting together</li>
    <li><strong>Stack</strong> — members of a type that currently sit next to each other</li>
    <li><strong>Orphan</strong> — a member of a type that is not in the stack (same type, wrong place in the list)</li>
  </ul>
  <div class="note">
    2D analysis is newer than SNP grouping and still being refined. Treat the
    boxes as a map of local similarity, not as a finished classification.
  </div>

  <h3 id="cl-understanding">4.5 Group explorer</h3>
  <p>
    After k-mer or SNP grouping, the <strong>Group explorer</strong> lists every
    group in the same top-to-bottom order as the alignment. A <strong>Groups</strong>
    menu appears in the menu bar; the dock button parks the explorer there
    (the other menus, except Input, Actions and Groups, have the same detach/dock handle).
  </p>
  <ul>
    <li>Expand a group for copy buttons: names, FASTA, ungapped FASTA, ungapped consensus</li>
    <li>Click a sequence name to select it in the alignment; click again to unselect. <em>Select</em> toggles the whole group</li>
    <li>Find supports substring or <em>.*</em> regex, shows all hits, and offers nearest-name suggestions as you type</li>
    <li><em>On/Off</em> uncolours that group only. The colour picker changes the group colour. <strong>Hide colours</strong> (toolbar) switches every group colour off for now and <strong>Show colours</strong> brings them back; the groups are kept</li>
    <li><strong>&#8645;</strong> on a group, or <strong>Gather all</strong> in the toolbar, moves the members next to each other in the alignment (one group, at the place of its first member; all groups in list order with unassigned last). Undo restores the order</li>
    <li>Arrows or drag reorder groups in the list and move their sequences together in the alignment</li>
    <li>Characters lists exclusive bases (only this group) and shared bases (common here, also found elsewhere); click a position to jump there</li>
    <li>Hovering a group highlights member sequences in the alignment</li>
    <li>Close hides the explorer; <strong>Clear all</strong> removes group data and the Groups menu</li>

    To insert a consensus <em>row</em> into the alignment, select the members

  <p>
    Folded under 2D analysis as <strong>Legacy squint mask</strong>. It is the

  <h3 id="di-checks">5.2 Highlight Diffs &amp; Variable Sites</h3>
  <p>
    <strong>Use case:</strong> exploring a long alignment that has several diagnostic
    polymorphic columns scattered far apart, pigeonholed among long runs of similarity.
    The goal is to see all the significant columns together, in close visual proximity,
    in a single view - for this kind of inspection, highly-similar columns carry no
    diagnostic information and actively get in the way of comparing the columns that
    matter. <strong>Variable sites only</strong> removes every similarity column from
    view entirely, so the differences that were previously separated by long distances
    become directly observable next to each other.
  </p>
  <p>Two checkboxes control visual filtering of conserved positions. They cannot be combined:
  turning on <strong>Variable sites only</strong> pauses <strong>Highlight diffs</strong> (with a
  message) and turning it off brings Highlight diffs back; ticking Highlight diffs while Variable
  sites only is on switches that one off.</p>
  <ul>
    <li>
      <strong>Highlight diffs</strong> - dims fully-conserved columns to 40% opacity and sets
      the variable ones in bold. Works in Full, Block and Canvas (the Reads view has its own
      renderer and does not apply it).
      Rapidly reveals where variation occurs.
    </li>
    <li>
      <strong>Variable sites only</strong> - hides conserved columns entirely,
      showing only positions with variation. Useful for scanning SNP-dense regions.
      Works in Full, Block and Canvas (in Canvas and Block the hidden runs collapse to the same
      marker cells, and the ruler, consensus row, selections and editing follow the shown columns).
    </li>
  </ul>
  <p>
    A column's "dominant pattern" is whichever state the largest group of sequences
    shares at that position - a specific base, or a gap. Gaps are not all treated
    alike: a gap that falls outside a sequence's own first-to-last real-base span
    (a leading or trailing gap, because that sequence simply doesn't reach this
    column) is missing data and is excluded entirely from the count. A gap that
    falls inside that span is a real deletion and is counted on equal footing with
    A/C/G/T, as a legitimate state in its own right - not specially exempted the
    way a substitution would be. A sequence counts as "differing" from a column if
    its own state (base or internal gap) isn't the dominant one. This matters most
    on alignments with substantial insertion/deletion variation - repeat or
    transposable-element families in particular - where indel polymorphism is often
    the majority of the real variation, not base substitution.
  </p>

  <h4 id="di-var-threshold">5.2.1 Variable-Sites Threshold</h4>
  <p>
    Next to the <strong>Variable sites only</strong> checkbox, a <strong>threshold
    slider</strong> (with a paired number box for typing an exact value) controls the
    minimum amount of sequences that must differ from the column's dominant pattern for
    it to be considered "variable". A small dropdown to its left switches what that
    number means:
  </p>
  <ul>
    <li>
      <strong>%</strong> — a percentage of all sequences, 0-100 in 1% steps.
      <strong>0%</strong> shows every column unfiltered; <strong>≥20%</strong> requires
      at least a fifth of sequences to differ; <strong>≥100%</strong> requires all but
      one sequence to differ (the most that can: one of them is the consensus); every
      percentage is capped there. Percentages work consistently across alignments of any size:
      for a 5-sequence alignment ≥20% means at least 1 sequence, for a 200-sequence
      alignment it means at least 40.
    </li>
    <li>
      <strong>count</strong> (default, at 1) — an exact absolute number of sequences, 0 up to
      one less than the total loaded, since at most that many can differ from a column's consensus
      (the slider's range updates automatically). <strong>≥1</strong>, the
      default, shows a column the instant even a single sequence differs, with no rounding at
      all: fully identical columns are dimmed or hidden, as the two checkboxes promise.
      <strong>0</strong> turns the filter off (every column counts as variable).
    </li>
  </ul>
  <p>
    Percentage mode rounds up to a whole sequence count (<code>Math.ceil</code>), which
    on small alignments can jump by more than one sequence between adjacent percentages
    - e.g. at 10 sequences, both 10% and 11% look like reasonable neighbouring settings,
    but they require 1 and 2 sequences respectively, so a column with exactly one
    differing sequence can flip from shown to hidden across that single percentage
    point. Percentage mode also has a related blind spot on real alignments: a region
    can be biologically highly variable while spreading that variation across many
    neighbouring columns, each affecting only a handful of sequences - staggered,
    independent insertions in a repeat family are a common example - so no single
    column ever reaches even a modest percentage threshold, and the whole region gets
    hidden as if it were conserved. Switch to <strong>count</strong> mode and set it to
    <strong>1</strong> when a flagged "conserved" region looks suspicious on inspection -
    it surfaces the individually-rare variants a percentage cutoff was built to filter out.
  </p>
  <h4 id="di-var-breakpoints">5.2.2 Breakpoint Markers</h4>
  <p>
    When <strong>Variable sites only</strong> is active, a <strong>Breakpoints</strong> checkbox
    (enabled by default) inserts thin <code>⋮</code> separator columns between visible
    variable columns where conserved columns were hidden. Each breakpoint shows a tooltip
    with the count and position range of hidden columns (e.g. <em>"12 columns hidden (positions 45–56)"</em>).
  </p>
  <ul>
    <li>Breakpoints preserve visual context — you can see <em>where</em> conserved regions were removed, not just that they are gone.</li>
    <li>Breakpoint columns are non-interactive: they cannot be selected, edited, or included in exports.</li>
    <li>Uncheck <strong>Breakpoints</strong> to glue visible columns together without separators (original behaviour).</li>
  </ul>
  <p>
    <strong>Use case:</strong> the marker's default grey shading and <code>⋮</code> glyph are
    a sensible default, but not always right for every screen or every printed figure - a
    grey mark can be hard to spot against a busy background, easy to confuse with actual
    sequence data at a glance, or simply not the house style for a publication figure. A
    small <strong>▾</strong> button next to the Breakpoints checkbox opens a tiny popover
    with two independent controls: a colour swatch for the marker's shading, and a symbol
    dropdown (<code>⋮</code>, <code>¦</code>, <code>:</code>, <code>•</code>, <code>❘</code>,
    or <strong>(empty)</strong> for no glyph at all — just a coloured strip marking where
    columns were hidden). Both choices are saved and restored automatically the next time
    you open the viewer.
  </p>
  <p>Both features can be combined with Codon analysis.</p>

  <h3 id="di-codons">5.4 Codon Analysis</h3>
  <p>
    Activates codon-aware viewing for coding sequences (CDS) in any nucleotide alignment
    (IUPAC ambiguity codes allowed; a codon containing one translates to X). The length need
    not be a multiple of 3. The reading frame is chosen automatically (most rows starting
    with ATG, then fewest stops) or set with the <strong>Frame</strong> selector next to the checkbox. Full, Block and Canvas draw the
    annotations below.
  </p>
  <p>
    <strong>By gene.</strong> With an annotation track that has CDS features (<a href="#an-track">6.4</a>),
    <strong>Frame: Auto</strong> (or <strong>Genes</strong>) analyses each gene separately: its columns are read in its
    own frame and strand (a minus-strand gene is translated from its reverse complement, so its codon
    positions run right to left), and columns outside the genes get no codon marks. That is what a whole
    mitogenome or a multi-gene region needs; one frame across it would put stops everywhere outside the
    first gene. Where genes overlap (ATP8/ATP6, ND4L/ND4, ND5/ND6) the later gene's codons on the shared
    bases go to a second translation row, so its start or stop codon is still shown; the bases keep the
    first gene's codon positions. In Block mode each block has only the translation rows its genes need:
    none in a block without CDS, a second one only where genes overlap. A gene whose last codon is cut to <code>T</code> or <code>TA</code> (a
    stop completed by polyadenylation of the mRNA, as GenBank notes it) shows a stop over those bases, but only when the genetic code in use has TAA as a stop. A BED
    feature counts as a CDS when its description column starts with <code>CDS</code>, or, without a
    description, when its name is not a tRNA, rRNA, origin or control-region name. Loading an annotation
    that looks mitochondrial (tRNAs, rRNAs, ND/COX/ATP/CYTB: at least 10 such features, or every feature,
    as in a one-gene file) while the code is Standard switches the <strong>Code</strong> to Vert Mito and says so. <strong>Copy AA</strong> and <strong>Save AA</strong>
    then give one record per sequence and gene, each read in the gene's direction. <strong>AA only</strong> (Codon bar, or
    the checkbox next to Codon analysis) shows the translation in place of the nucleotides, one amino-acid line per
    sequence, in Full, Block and Canvas; rows in a block without a CDS keep their nucleotides, and the names work as usual. A codon with IUPAC
    ambiguity letters translates to the amino acid all its readings share (<code>CCN</code> = P), else X.
    Checked against GenBank: the 13 CDS of NC_069019.1 translate exactly to the record's own
    <code>/translation</code> fields (functional test "Codon analysis by gene (oracle)").
  </p>
  <p>Select the appropriate genetic code from the <strong>Code</strong> dropdown (15 variants):</p>
  <table>
    <tr><th>Code</th><th>NCBI Table</th><th>Key Differences from Standard</th></tr>

    <tr><td>Ciliate</td><td>6</td><td>TAA/TAG = Gln</td></tr>
    <tr><td>Echino Mito</td><td>9</td><td>AAA = Asn, AGA/AGG = Ser, TGA = Trp</td></tr>
