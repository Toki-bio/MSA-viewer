  <p><strong>Find a function</strong> (the bar in the menu row, or <kbd>Ctrl+K</kbd>) lists every function of the program, menu by menu. Type part of its name or of its tooltip; <kbd>Enter</kbd> or a click runs it as the control itself would, a switch is flipped, an option is chosen, and a number or colour opens its menu with the cursor in it. What cannot run now is shown dimmed. <section id="server">
  <h2>11. Server Features</h2>
  <p>
    The optional Node.js server (<code>server.js</code>) provides backend services.
    Start it from the project directory:
  </p>
  <pre>node server.js</pre>
  <p>The server listens on port 3000 by default.</p>
  <div class="note">
    <strong>Access key.</strong> When it starts, the server prints a link such as
    <code>http://localhost:3000/?key=...</code> (<code>start-server.bat</code> shows it too). Open that link
    once in each browser you use; after that <code>http://localhost:3000</code> works there. The key is kept in
    <code>~/.viewalign/access-key</code>, readable by you only, and stays the same across restarts (delete the
    file and restart for a new one). Without the key the viewer opens and says so in a note, and the server
    refuses to read files, reach SSH servers, add or delete databases or run MAFFT/BLAST. This keeps other
    users and programs on the same computer from using your server.
  </div>

  <h3 id="sv-setup">11.1 Setup</h3>
  <p>Requirements:</p>
  <ul>
    <li>Node.js - the server code needs version 14 or later (optional chaining, <code>??</code>); tested with Node.js 24</li>
    <li><strong>MAFFT</strong> - only for the <code>/api/mafft</code> endpoint (optional; path set by <code>MAFFT_BIN</code>). The viewer itself realigns in the browser</li>
    <li><strong>BLAST+</strong> - for local BLAST search (optional)</li>
    <li><strong>samtools</strong> - only for the <code>/api/bam2sam</code> endpoint (optional; the viewer reads BAM and CRAM itself)</li>
    <li><strong>SSH key and PuTTY <code>plink</code></strong> - for remote file access (optional): the server reaches SSH hosts by running <code>plink</code>, which must be on the PATH</li>
  </ul>
  <p>Environment variables:</p>
  <table>
    <tr><th>Variable</th><th>Purpose</th></tr>
    <tr><td><code>CORS_ORIGIN</code></td><td>Allowed origin for cross-origin requests (default: localhost only)</td></tr>
    <tr><td><code>SSH_KEY_PATH</code></td><td>Path to SSH private key for remote access</td></tr>
    <tr><td><code>MAFFT_BIN</code></td><td>Path to the native MAFFT binary used by <code>POST /api/mafft</code></td></tr>
    <tr><td><code>PORT</code>, <code>HOST</code></td><td>Port (default 3000) and bind address (default <code>127.0.0.1</code>; set <code>HOST=0.0.0.0</code> to accept other machines)</td></tr>
    <tr><td><code>ALLOW_REMOTE_FILE_ACCESS</code></td><td>Reading files, SSH, adding or deleting databases and running MAFFT/BLAST answer only clients on the same machine; <code>1</code> lets other machines use them (they still need the access key)</td></tr>
    <tr><td><code>LOCAL_FILE_ROOTS</code></td><td>Folders the server may read files from (default: the server folder and your home folder; never hidden folders such as <code>~/.ssh</code>)</td></tr>
    <tr><td><code>STATIC_SERVE_ALL</code></td><td>The server serves only the viewer's own files, snapshots and added databases; <code>1</code> serves the whole folder (development pages)</td></tr>
    <tr><td><code>CHILD_OUTPUT_MAX_BYTES</code></td><td>Largest output accepted from a program the server runs (ssh, samtools)</td></tr>
    <tr><td><code>ALLOWED_HOSTS</code>, <code>TAILSCALE_IP</code></td><td>Host names (comma-separated) or a Tailscale address, besides <code>localhost</code>, that requests may use; blocks DNS-rebinding pages</td></tr>
  </table>

  <h3 id="sv-mafft">11.2 MAFFT Integration</h3>
  <p>
    The server executes MAFFT as a child process with whitelisted options only.
    Input is sanitised - only recognised MAFFT flags are passed to the binary.
    Strategy flags such as <code>--auto</code>, <code>--localpair</code>, <code>--globalpair</code>,
    <code>--genafpair</code> and <code>--maxiterate</code> are accepted. The viewer's Realign buttons do
    not use this endpoint (they run MAFFT in the browser, §3.1).
  </p>

  <h3 id="sv-ssh">11.3 SSH Remote Access</h3>
  <p>
    Fetch alignment files from remote servers via SSH. The servers are listed in
    <code>ssh-servers.json</code> beside <code>server.js</code> (copy <code>ssh-servers.example.json</code>), and reached with PuTTY's <code>plink</code> and the key path.
    <strong>Check Queue</strong> in the Input menu loads a file whose path was written to a queue file on the remote host (see <code>REMOTE_PUSH_TO_LOAD_GUIDE.md</code>); the browser never polls by itself. Files are read with <code>cat</code> and streamed
    to the browser - no temporary files on disk.
  </p>
  <div class="note">
    <strong>Security:</strong> Paths may contain letters, digits, spaces and
    <code>_ @ % + = : , . / ~ -</code> only, and may be absolute, relative, or start with
    <code>~</code> (expanded on the remote host). Blocked: a <code>..</code> segment, quotes,
    <code>$</code>, backticks, backslashes, newlines, redirections and a leading <code>-</code>.
  </div>

  <h3 id="sv-bam">11.4 BAM/CRAM Support</h3>
  <p><strong>Endpoint:</strong> <code>POST /api/bam2sam</code></p>
  <pre>{
  "bamPath": "/data/alignments/sample.bam",
  "region": "chr1:1000-5000"
}</pre>
  <p>
    Converts BAM/CRAM to SAM using <code>samtools view -h</code>.
    The <code>region</code> field is optional and restricts output to a genomic interval.
    Resulting SAM is parsed client-side with CIGAR expansion.
  </p>

  <h3 id="sv-security">11.5 Security</h3>
  <ul>
    <li><strong>Access key</strong> - file, SSH, database and MAFFT/BLAST routes need the key cookie set by the link the server prints (above)</li>
    <li><strong>CORS</strong> - restricted to localhost by default; configurable via <code>CORS_ORIGIN</code></li>
    <li><strong>Request body limit</strong> - capped at 10 MB</li>
    <li><strong>Path traversal</strong> - <code>..</code> and shell metacharacters blocked in file paths</li>
    <li><strong>MAFFT argument whitelist</strong> - only recognised options pass to the binary</li>
    <li><strong>BLAST parameter validation</strong> - no arbitrary flag injection</li>
    <li><strong>SSH key path</strong> - auto-detected from <code>os.homedir()</code>, overridable via <code>SSH_KEY_PATH</code></li>
  </ul>
</section>

<section id="tips">
  <h2>12. Tips &amp; Best Practices</h2>

  <h3 id="tp-large">12.1 Large Alignments</h3>
  <ul>
    <!-- Compact mode removed -->
    <li>Turn on <strong>Highlight Diffs</strong> to visually compress conserved regions</li>
    <li>Use <strong>Block mode</strong> with smaller block sizes (40-60 columns; the minimum is 40) for very wide alignments</li>
    <li><strong>Canvas</strong> is the default view and scrolls smoothly at any size; <strong>Block</strong> is drawn the same way; from about 100,000 residues, <strong>Full</strong> draws a window of the alignment instead of every cell</li>
    <li>For extremely large files (&gt; 500 sequences x 5,000 columns), consider splitting the input</li>
    <li>Use <strong>Variable sites only</strong> with the <strong>threshold slider</strong> to strip conserved columns and focus on variation. Set the threshold to ≥20% or higher to highlight only the most polymorphic sites.</li>
  </ul>

  <h3 id="tp-figures">12.2 Publication Figures</h3>
  <ul>
    <li><strong>Block mode</strong> + <strong>Amino Acid: Jalview-like</strong> colour scheme for amino acid alignments</li>
    <li><strong>Export SVG</strong> for vector graphics - refine in Inkscape or Illustrator</li>
    <li><strong>Export RTF</strong> for Word-compatible alignments with conservation shading</li>
    <li><strong>Dot plot -> Export SVG</strong> for high-quality dot plots</li>
    <li>Use <strong>Snapshots</strong> to save exact figure settings for reproducibility</li>
    <li>Set Name Length to a short value (e.g., 10-15 characters) for cleaner figures</li>
    <li>Adjust zoom to fit the alignment width on your target page</li>
  </ul>

  <h3 id="tp-coding">12.3 Coding Sequence Analysis</h3>
  <ul>
    <li>Codon mode is for coding sequences; on non-coding alignments (repeats, SINEs) most gaps are not multiples of 3 and the track fills with stops and <code>!</code> marks</li>
    <li>Select the correct genetic code - mitochondrial genes use different codes than nuclear</li>
    <li>Red <code>!</code> marks (frameshifts) in a coding alignment often indicate sequencing errors or pseudogenes</li>
    <li>Clusters of non-synonymous mutations (red underline) may indicate positive selection</li>
    <li>Mid-CDS stop codons suggest pseudogenisation or misannotation</li>
    <li>Combine <strong>Highlight Diffs</strong> + <strong>Codon Analysis</strong> to rapidly scan for impactful mutations</li>
    <li>The translation track confirms the reading frame - if it looks garbled, check your frame</li>
  </ul>

  <h3 id="tp-clustering">12.4 Clustering Best Practices</h3>
  <ul>
    <li><strong>Always trim</strong> alignment ends before SNP grouping — ragged edges inflate gap-based scores</li>
    <li>Start with <strong>Group by k-mer</strong> for an overall split, then <strong>Find SNP groups</strong> (optionally with Split existing groups) for exclusive columns</li>
    <li>Start SNP knobs from <strong>Defaults</strong>, then tighten if groups look noisy</li>
    <li>If a run returns nothing, press <strong>Clusterability</strong> before changing settings by hand — it shows which parameters move the result on your data and which are inert</li>
    <li>Use <strong>Preview</strong> (trim) and review the Group explorer before treating colours as a classification</li>
    <li>For small families, lower <em>Min Size</em> to 2 and reduce quality thresholds</li>
    <li>For highly conserved families, increase quality thresholds (90%+ for small groups)</li>
    <li>After grouping, copy FASTA from the explorer or use <strong>+ Consensus Below</strong> to insert a representative row</li>
    <li><strong>Show 2D</strong> maps where a pattern sits; it does not replace SNP grouping. Paint modes never reorder; Alt+click a rectangle to stack that type (Undoable)</li>
    <li>Save working SNP parameter sets as named presets for reproducibility</li>
    <li>Groups of size 1 are discarded — they may represent singletons or sequencing artefacts</li>
  </ul>
</section>
