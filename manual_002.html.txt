<section id="input-menu">
  <h2>2. Input Menu</h2>
  <p>
    The Input menu is the starting point for loading data into the viewer.
    It appears as the leftmost dropdown in the menu bar.
  </p>

  <h3 id="in-fasta">2.1 FASTA / MSF Input</h3>
  <p>
    Paste your alignment directly into the textarea. Both FASTA and MSF formats are
    auto-detected. Click <strong>Load</strong> (or press <kbd>Ctrl+L</kbd>) to process
    the data. The <strong>Clear</strong> button empties the textarea.
  </p>
  <p>
    The viewer auto-detects sequence type (DNA, RNA, protein) from the residue composition
    of the first few sequences. Protein FASTA input is preserved as amino-acid data; unknown
    protein characters are normalised to <code>X</code> rather than converted to nucleotide
    ambiguity characters.
  </p>
  <p>
    <strong>Protein alignments.</strong> Display, shading, consensus, motif search
    (forward strand), statistics, trees (p-distance over amino acids), editing, MAFFT
    realignment (Seq Type <em>Protein</em>) and export all work on protein. The dot plot,
    SNP and k-mer grouping, the Repeat/TSD finder and codon analysis were designed for
    nucleotides: they run on amino-acid letters, but strand options, inverted repeats
    and TSDs have no meaning there. MAFFT itself drops <code>*</code> and does not know <code>U</code> (selenocysteine),
    <code>O</code> (pyrrolysine) or, in nucleotides, letters that are no base code: the viewer sends
    such residues as <code>X</code> (or <code>N</code>) and writes the original letters back into
    the result, so they are kept.
  </p>
  <p>
    GenBank flatfiles can also be pasted directly. Records beginning with <code>LOCUS</code>
    are parsed for header metadata, <code>FEATURES</code>, and the <code>ORIGIN</code> sequence.
    The imported sequence is displayed as a normal alignment row; feature coordinates are stored
    with the parsed record for future annotation features.
  </p>

  <h3 id="in-file">2.2 File Loading</h3>
  <p>
    The drop zone accepts files via drag-and-drop. Click the zone to open a file picker.
    The file type is recognised from the content, not the extension (1.2). After loading,
    the file name appears in the top-right info panel.
  </p>

  <h3 id="in-url">2.3 URL Loading</h3>
  <p>
    Paste a URL to a raw alignment file (e.g., a GitHub raw link or a public server path)
    into the Input box and click <strong>Load</strong> (or press <kbd>Ctrl+L</kbd>); a pasted
    <code>http(s)://</code> address is recognised as a location rather than data. The viewer
    fetches the file via <code>fetch()</code> with CORS restrictions. The same file can be
    opened directly with <code>?url=</code> in the page address (1.2).
  </p>

  <h3 id="in-ssh">2.4 SSH Remote Loading</h3>
  <p>
    When the server is running with SSH configuration, an SSH row appears in the Input menu.
    Select a server, enter a file path, and click <strong>Fetch</strong> or press <kbd>Enter</kbd>.
    The file is read via <code>cat</code> on the remote host and streamed to the browser.
  </p>
  <div class="note">
    <strong>Security:</strong> Path traversal (<code>..</code>) and shell metacharacters are
    blocked. Files are never written to disk on the server.
  </div>

  <h3 id="in-sam">2.5 SAM / BAM / CRAM</h3>
  <p>
    <strong>SAM on its own</strong> (pasted or opened) becomes an alignment. Primary mapped reads are kept;
    the top row, <code>REF</code>, is the majority base of the reads at each position, so no reference file
    is needed. Inserted bases get their own columns, with gaps in every other row, so each read's other
    bases stay in their reference column; soft-clipped bases are left out. If the reads map to more than
    one reference, the reference with the most reads is shown and the others are named in the status line.
    To look for mutations, open the real reference first and the reads onto it (below): <code>REF</code> here is the
    reads' own majority, so a change all the reads carry is part of it and is not seen as a change.
  </p>
  <p>
    <strong>SAM, BAM or CRAM onto a reference:</strong> open the reference sequence first (FASTA or GenBank),
    then the reads file (<strong>SAM/BAM</strong> button, Input, drag and drop, or Add sequences; in a link,
    <code>?reads=&lt;url&gt;</code> next to <code>?url=</code> opens both in Reads mode). The reads go
    on the loaded sequence named as in the file's <code>@SQ SN:</code> line; a name that differs only by a
    <code>chr</code> prefix, a version (<code>.2</code>) or case also matches, as does a single loaded sequence of
    exactly the reference's length (the message says so), and a region cut out with
    <code>samtools faidx</code> (a sequence named like <code>chr7:1001-2000</code>): the reads, in chromosome
    coordinates, are shifted onto it. A SAM without <code>@SQ</code> lines takes the references from its
    reads. Everything happens in the browser, so no server is needed: BAM is decompressed directly, and CRAM,
    which stores reads as differences from the reference, is decoded against the loaded sequence by the
    JBrowse CRAM reader (<code>@gmod/cram</code>, loaded only when a CRAM is opened). BAM and CRAM are recognised
    by their content, whatever the file is called. Opening a BAM or CRAM with nothing loaded shows how to load
    it instead.
  </p>
  <p>
    <strong>A whole-genome BAM:</strong> select the BAM <em>together with its index</em> (<code>.bai</code>, from
    <code>samtools index</code>) &mdash; both files at once in the SAM/BAM dialog, or dropped together. Only the
    compressed blocks holding reads of the loaded sequence are then read (as IGV does), so load the gene first,
    cut out as <code>samtools faidx genome.fa chr7:117480025-117668665</code> writes it: the reads of that region
    are read and shifted onto it, and the message says how much of the file was read. Without an index the
    whole BAM is decompressed, which a browser cannot do above about 500 MB (the message says what to do).
    Only <code>.bai</code> indexes are read (not <code>.csi</code>, nor CRAM's <code>.crai</code>).
  </p>
  <p>
    <strong>Which reads count:</strong> unmapped reads are dropped. Secondary, supplementary, QC-failed and duplicate reads are
    hidden (the message says how many; <strong>Options</strong> shows them) and never count. Every other read is kept (up to 2,000,000) and counts for the
    coverage, the allele counts and the sample row; the view draws at most 50 reads starting in each 100 bp
    (a fixed random sample, as igv.js does), and marks the windows where reads were not drawn.
  </p>
  <p>
    <strong>The Reads view:</strong> the reference, the ruler, a <strong>coverage</strong> row and the reads,
    packed into tracks. Coverage counts every read; where the non-reference bases reach 20% of the reads the bar
    is split into base colours. Hover a coverage column for its counts per base and strand
    (<code>A: 37 (49%, 20+, 17&minus;)</code>), deletions and insertions; click it to sort the reads by their base
    there (the most common other base first, the reference base last). Read bars are pink on the forward
    strand and blue on the reverse strand (a change seen on one strand only is a common artefact), faded when
    their mapping quality is 0; mismatching bases are letters, deletions grey, insertions orange ticks (the
    inserted bases are in the read's tooltip). <strong>Show bases</strong> draws every base.
  </p>
  <p>
    <strong>Moving around:</strong> drag the reads to move the view, or use the wheel. Ctrl+wheel, the
    <strong>&minus;</strong> and <strong>+</strong> buttons or a double click zoom, from single bases to the whole region; the
    length on screen is beside the buttons. Under 7 pixels per base the letters become ticks, past about 1.2 million aligned bases on screen (some 40 kb at 30&times;, all of a few long reads) only the
    coverage is drawn, and mixed sites stay marked in it at any zoom. The box next to it goes to a position
    (<code>12,345</code>), a range, which then fills the view (<code>12,000-13,000</code>), a gene of the loaded annotation
    (any case, or the start of its name), or, on a region row like <code>chr7:1001-2000</code>, a position in the file's own
    coordinates (<code>chr7:1,500</code>). The view runs from the first read to the last.
  </p>
  <p>
    <strong>Rows beside the reads:</strong> with an annotation, a gene row shows exons, the coding part taller, and the strand; click a
    gene to go to it. Open a <code>.vcf</code> or <code>.vcf.gz</code> with the SAM/BAM button after the reads for a row of sites
    (blue a substitution, orange an indel) and a thin row per sample (up to 8: grey reference, blue heterozygous, light blue
    homozygous for the change); hover for the details, click to open the reads there.
    <strong>Compact</strong> gives rows of 4 pixels for a deep place.
  </p>
  <p>
    <strong>Options:</strong> a minimum MAPQ leaves reads out of the picture, the coverage and the calls; <strong>Reads per 100 bp</strong> sets how many are drawn; the hidden kinds of read
    can be drawn, but never count. <strong>Sort by</strong> orders the rows by the read at the marked column, or else the middle of
    the view. <strong>Colour by</strong> shows strand, first-of-pair strand, MAPQ, insert size (red over 3 times the median, blue
    under a third), pair orientation or a tag. <strong>Group by</strong> splits the pile into labelled parts: by strand, kind of read,
    a tag such as HP, or the base at a column, which separates the two alleles of a site. <strong>View as pairs</strong> puts mates on
    one row with a line between them. <strong>Show soft clips</strong> turns the dashed boxes off. A change on a poor base is drawn fainter (Phred 5 to 20). Right click a read to copy it or its soft
    clips, go to its mate, or sort or group by the base there.
  </p>
  <p>
    <strong>Checking a gene for mutations from reads:</strong>
  </p>
  <ol>
    <li>Open the gene: a GenBank file with its CDS (the CDS, tRNA and rRNA features become the annotation
      track: <code>join()</code> exons, <code>complement()</code>, <code>/codon_start</code>;
      <code>/transl_table</code> sets the genetic code), or a FASTA plus a BED annotation (BED12 for exons and
      the coding part).</li>
    <li>Open its reads. <strong>Variants</strong> (next to Show bases) lists every change the reads carry:
      position, change, zygosity, depth, allele %, alt and reference reads on each strand, and for each gene
      the effect (synonymous, missense, stop gained or lost, start lost, frameshift, in-frame deletion or
      insertion, splice site within 2 bases of an exon, intron, UTR), the coding change (<code>c.419G&gt;A</code>,
      counted from the A of the start codon, complemented on a minus-strand gene) and the amino-acid change
      (<code>p.R140Q</code>, <code>p.S51*</code>, <code>p.G170fs</code>). Notes flag alt reads on one strand
      only, low depth, and heterozygous indels. Click a row for its reads (sorted by their base there),
      double-click for its column in the alignment. <strong>Copy table</strong> / <strong>Save .tsv</strong>
      take it to a spreadsheet. A change is called where a second base has at least 20% of the reads (and two
      reads; heterozygous below 80%), from bases of quality 13 or more, with N where fewer than 3 reads cover a
      base; indels are called as whole events, left-aligned in repeats.</li>
    <li><strong>Sample &rarr; row</strong> adds the sample under the reference as an ordinary row and switches to
      the Canvas view: the base most reads carry, an IUPAC code for two (heterozygous, e.g. R = A/G), a gap where
      most reads carry a deletion, extra columns where most carry an insertion, N under 3 reads.
      Heterozygous indels cannot be shown in one row (they are in the Variants list). Another sample's reads
      file gets its own row, <code>&lt;reference&gt;_&lt;file name&gt;</code>. Undo removes a row again.</li>
    <li>Switch on <strong>Codon analysis</strong> (Display menu): with genes on the annotation track each CDS is
      translated in its own frame and strand, exons joined; each change is marked synonymous or
      non-synonymous against row 1, a codon with a heterozygous base by both its alleles, a possible stop as a
      stop, and an indel that breaks the frame as a frameshift. A translated codon's tooltip gives its number
      in the gene (<code>R (CGA), codon 140</code>).</li>
    <li>Codon realignment (<strong>MACSE&hellip;</strong>) is for coding sequences: rows with stop codons in every
      frame (a gene with its flanks or introns) get a warning first, since an aligner explains each stop with
      frameshifts. To realign one gene, click it on the annotation track (its columns are selected) and use
      <strong>Realign Block</strong> (Alignment menu). Its summary counts frameshifts inside the sequences, not the padding of
      fragments that start or end inside a codon.</li>
  </ol>
  <p>
    The optional server also exposes <code>POST /api/bam2sam</code> (see 11.4), which converts a BAM or
    CRAM file on the server's disk to SAM text with <code>samtools view -h</code>, for scripted use.
  </p>

    <li>The <strong>chromosome list</strong> beside the zoom buttons changes chromosome; the jump box takes
      <code>chr:position</code>, a position, or a chromosome name. <strong>Close genome</strong> closes the
      genome and its reads.</li>
    <li>Reads are shown as in the Reads view (above), read for the window on screen. A view whose reads would
      cost more than 16 MB of compressed BAM shows coverage of nothing: zoom in and the reads appear. The
      sample row is called for the window on screen.</li>
    <li>Opening a genome closes the open alignment (the viewer asks first) and clears Undo.</li>
    <li>Not read in the genome view yet: CRAM and <code>.crai</code>, <code>.csi</code> indexes, a compressed
      FASTA (<code>.fa.gz</code>), VCF rows, and Sample &rarr; row. The viewer says which file is missing or
      not readable when the selection does not fit.</li>
  </ul>
